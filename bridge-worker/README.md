# Vesper Chat isolated bridge

This service is separate from the existing Vesper MCP: each OAuth grant or direct bearer code is bound to exactly one external-assistant connection. It exposes only `read_messages` and `send_reply`, and checks revocation on every tool invocation. It does not expose Ash's conversation, diary, memory, albums, or other connections. A paired Vesper device creates and revokes connections using `/api/conversation-bridge`; only a SHA-256 hash of each connection code is stored. Enter the code only on the HTTPS OAuth authorization page or in the provider's secret storage, never in a chat message.

The bridge currently supports text-only one-to-one conversations; it does not yet support images/stickers or group chats. Work may subscribe to the MCP `message.created` event for its own connection. A scheduled worker checks for new messages once per minute, verifies callbacks before use, signs deliveries and retries transient failures with a stable event ID. Work must be instructed to subscribe first, read pending messages, and use `send_reply`. Each user message accepts one assistant reply, so an overlapping event and pending read cannot create duplicate replies. The `pending` array identifies user messages without a reply. `send_reply` requires the source message ID and a client-generated idempotency ID. The device polls while a bridge conversation is open. Actual Work event availability and Muse connector and wake behavior must be tested with the real clients before claiming end-to-end availability.

## Local verification

`node --experimental-strip-types tools/test-conversation-bridge.mjs` tests isolation, revocation and idempotency using an in-memory SQLite D1 adapter. `node --experimental-strip-types tools/test-conversation-bridge-events.mjs` tests signed callback verification, per-connection delivery, retries, and revocation. `tools/test-conversation-bridge-oauth.mjs` tests a local HTTPS Worker with a disposable seeded test binding. Do not use real connection codes for tests. Worker bundling: `npx wrangler deploy --dry-run --config bridge-worker/wrangler.jsonc`.
